## 2) الاستنتاجات النوعية مقابل الدليل

**أ) التدرّج = بنية مفهومة، وليس رقم أسبوع فقط.** Calistree يقدم skill trees وAlpha Progression يقدم مقارنات للأداء. بالنسبة لبرنامج مبتدئة A/B، نحتاج إظهار ما الذي تغيّر في الحركة مع الاحتفاظ بقيودها. التقدّم لا يعني الإذن التلقائي بتغيير الجرعة.

**ب) السياق يسبق اختيار البديل.** Freeletics يوثق تعديلات الوقت والهدوء والمساحة وعدم توفر الأدوات. حركة مناسبة في النادي قد لا تكون عملية في غرفة ضيقة في البيت. لكن استبعاد منطقة عضلية **ليس** بديلًا عن تقييم الألم؛ مركز مساعدة Freeletics يحذر من استخدامه عند إصابة محتملة.

**ج) التسجيل الناجح سريع ويمكن إيقافه واستئنافه.** Strong وLadder وBoostcamp يركزون على تسجيل المجموعات والمؤقت وتعديل الحركات، بينما يذكر مستخدمون في Reddit عبء التبديل والتسجيل. هذه إشارات نوعية وليست حجمًا مثبتًا للسوق.

**د) البيلاتس ليس فيديو عشوائيًا.** Pilates Anytime ينظم الجلسات حسب الأداة/المستوى/الوقت، وEvolveYou يضعه في مسار منفصل عن المقاومة. لوح البيلاتس الأرضي الذي نستخدمه ليس Reformer؛ نحتاج فلاتر واضحة وبرنامجًا يراجعه مختص.

**هـ) وجبتان لا تعنيان نقص الخصائص.** Fitia يتيح تخصيص أنواع الطعام والوصفات وتنوع الوجبات وقوائم تسوق بمقاديرها. لدينا وجبتان وسناك اختياري؛ القيمة الأعلى هنا «تفضيل التنوع» وتوافق الغرامات مع قائمة المشتريات، لا زيادة عدد الوجبات.

**و) أكبر خطر عملي ليس في تصميم الواجهة بل في سياق الحفظ على iPhone.** Apple توضح استقلال تخزين Home Screen Web App عن Safari؛ نقل بيانات المستخدم بين السياقين ليس مزامنة تلقائية. هذا يؤثر على الثقة ويجب أن يسبق التحديثات الكبيرة.

## 4) التصميم المقترح — ثلاث رحلات تدعم منتجنا

### User Journey A: Skill Tree + Smart Swap

«تماريني» → جلسة A → حركة A03 «سحب مطاط» → «تغيير الحركة» → سبب محدد (غياب المطاط، حاجة لجلوس، مكان ضيق، صعوبة، أو أعراض) → **لو أعراض جديدة أو منع طبي: إيقاف وتقييم، لا توليد بدل تلقائي** → عرض شجرة بدائل مبينة العلاقة (نفس نمط الحركة / جزء من الهدف / تحميل مختلف) → بطاقة مساعدة + الأدوات + درجة مطابقة الفيديو → تأكيد للحصة فقط → حفظ `variantId` و`reason` و`equipmentContext` → عرض الأداء السابق **لنسخة الحركة نفسها فقط**.

**مقياس UX مقترح:** النسبة التي تنجح في اختيار بديل للمعدات الموجودة بعد قراءة علاقته بالحركة، والوقت وعدد النقرات وخطأ اختيار البديل الممنوع.

### User Journey B: 10-Minute Recovery-Compatible Session

«اليوم» → «اليوم وقتي 10 دقائق» → خيارات: راحة / جزء من جلسة A/B حسب حركات معتمدة / مشي مريح → إذا تم اختيار جزئية، يبقى السجل **partial** ولا يُحسب مكتملًا → سجل شعور بسيط بعده → تحديث ملخص الأسبوع دون تلاعب.

**مقياس:** الاستئناف بعد إغلاق الصفحة، الحفظ، والفهم الصحيح لمعنى الحصة الجزئية.

### User Journey C: Pilates Library

«البيلاتس» → اختيار الأدوات (مات، لوح بيلاتس أرضي، كرسي، بدون) → المدة (5/10/20) → الوضعية (جلوس/استلقاء/وقوف) → المستوى مبتدئة → قائمة حصص **مراجعة مسبقًا** فقط، مع الفيديو المطابق، ووسوم الحركة المؤجلة. عندما تكون المكتبة غير معتمدة تظهر «بانتظار المراجعة» لا جلسة تلقائية.

**مقياس:** جودة العثور على جلسة مطابقة للأدوات، نسبة العثور على حركة بدون فيديو، وفهم تحذيرها.

## 7) Research gaps / ما لا يمكن ادعاؤه

- المقارنة هنا **Desk Research**؛ لم نُجرِ اختبارًا متكافئًا مدفوعًا على كل منافس، ولم نحدد أسعار اشتراكات أو نسب احتفاظ أو تقييمات شاملة.
- الصور والواجهات والأسماء والشعارات والفيديوهات المحمية للمنافسين ليست مادة للنقل أو النسخ. نقتبس الفكرة والوظيفة مع تطبيق أصلي.
- نظام الشجرة لا يقرر آليًا أن المستخدم «جاهز طبيًا» لحركة أصعب.
- بعض الصفحات الرسمية تسوق فوائد عامة؛ لا نعاملها كأدلة سريرية شخصية.
- إمكانات Native iOS/Watch لا تفترض تلقائيًا في PWA منشور على GitHub Pages.
- النصوص والأفكار الجديدة **لم تُبرمج في هذه الجولة**؛ الهدف بحث وتحديد متطلبات قابلة للاختبار، وتبقى PR مسودة وفرع `main` دون تغيير.

**Decision:** أول تحسين قابل للقياس: «فهم البدائل وسياق أدواتي + حفظ حقيقي في PWA». ثانيًا «جلسة مركزة يمكن استئنافها». ثالثًا «Pilates Library مصنفة ومراجعة».
