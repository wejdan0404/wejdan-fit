# WEJDAN FIT — مراجعة UX / UI / Accessibility / Quality

**تاريخ العمل:** 23 نوفمبر 2026  
**النطاق:** تطبيق الويب المرفوع على GitHub Pages وملف Excel V7.  
**معيار التحقق:** تختلف مراجعة الكود والاختبارات المحلية عن اختبار iPhone الحقيقي وعن أبحاث المستخدمين.

## منهجية مختارة من مكتبة Skills التي أرسلتها المستخدمة

| المهارة/الأداة المطبقة منهجيًا | ما طُبق فعلًا | ماذا لا ندّعي؟ |
| --- | --- | --- |
| heuristic-evaluation / NNGroup | وضوح حالة الحفظ، توافق واجهات الطعام والتمرين، تقليل الإدخال اليدوي والرسائل غير الدقيقة | لم نستعن بمشاركين في دراسة مستقلة |
| information-architecture / progressive-disclosure | فصل «اليوم، تماريني، أكلي، تقدمي، المزيد» وإظهار التفاصيل عند الحاجة | لم نجرِ Card Sorting مع مستخدمات |
| form-design / error-handling-ux | فحص الأرقام والتواريخ، إيضاح نقص الماكروز، كشف خطأ الوجبة قبل الحفظ | لا توجد قاعدة بيانات مكونات موثقة تلقائيًا |
| responsive-design / keyboard-navigation / WCAG | RTL، تصميم الجوال 390px، رابط تخطي المحتوى، حبس التركيز في النوافذ، تقليل الحركة | لم نشغّل تحليل axe/WAVE رسميًا أو قارئ شاشة فعليًا |

## إصلاحات هذا الإصدار

1. **حساب المقادير:** إضافة مكونات متعددة؛ الجرامات والسعرات/100 جم والماكروز/100 جم اختيارية. الحساب يملأ نموذج وجبة جديدة بعد مراجعة المستخدم.
2. **نقص الماكروز:** القيمة الفارغة لا تُعرض بصفر موهِم؛ تظهر «غير مكتمل» حتى توثيق كل وجبة.
3. **المراجعة الأسبوعية:** آخر سبعة أيام—حصص المقاومة، الوجبات المسجلة، دقائق المشي، متوسط النوم عند إدخال بيانات.
4. **التواريخ:** منع إدخال تاريخ شكله صحيح لكنه غير موجود مثل 2026-02-31.
5. **الواجهة:** تحسين أزرار نوع يوم الكارب والجلسة لتُعلن حالتها، رابط تخطي المحتوى، وتحسين لوحة المفاتيح للنوافذ المنبثقة.
6. **الهوية:** استيراد شعار W كـSVG من نظام الهوية بدل كتابة حرف W مؤقت، مع إبقاء ألوان Figma كما هي.
7. **الجودة:** تشغيل الاختبارات عبر `node tests/regression.js` وإضافة Workflow في `.github/workflows/quality.yml`.
8. **الحفظ والخصوصية:** الإبقاء على مفتاح `wejdan-fit-app-v1` حتى لا تُمسح بيانات من استخدم النسخة السابقة.

## اختبارات محلية أُجريت

- JavaScript: `node --check app.js` و `node tests/regression.js` — نجحت.
- Chromium محليًا باستخدام Playwright مع تحميل HTML/CSS/JS داخل سياق معزول: حاسبة **150 جم × 130 kcal/100 جم + 100 جم × 165 kcal/100 جم = 360 kcal**، بروتين **35.1 جم** بقيم تجريبية — نجحت؛ لم تُستخدم بيانات غذائية حقيقية موثقة.
- تسجيل وجبة ومجموعة وعدّات وإنهاء جلسة ثم إعادة إنشاء الصفحة مع حفظ `localStorage` المحاكي — نجح.
- شاشة جوال بعرض **390px**: العرض والتمرير الأفقي والصور — نجح، ولا يوجد خطأ JavaScript مُبلّغ في هذا الاختبار.
- الوضع الداكن — نجح.
- ملاحظة: بيئة الفحص تمنع تصفح localhost وfile مباشرة؛ لذلك استخدمنا `page.set_content` لتشغيل الملفات في Chromium. **لم يُختبَر التثبيت الفعلي لـPWA من GitHub Pages على هاتف.**

## ما بقي مفتوحًا

- فحص التباين آليًا على جميع حالات Light/Dark، ومراجعة VoiceOver وTalkBack على هواتف فعلية.
- اختبار الأداء وOffline وService Worker على عنوان HTTPS المنشور بعد التحديث.
- تدقيق مكونات **89 وصفة** والحصص ومسببات الحساسية (الفول السوداني وجوز الهند) من مصادر غذائية موثوقة، لا مجرد أسماء وصفات.
- لا توجد مزامنة تلقائية بين الأجهزة أو بين التطبيق وإكسل؛ النسخ الاحتياطي يتم يدويًا عبر JSON.
- التدرج الرياضي يعتمد على السماح الطبي وتحمل الأعراض، ولا يرفع الأوزان تلقائيًا.
- هذه نتيجة **مراجعة خبير واحدة واختبارات وظيفية**، وليست دليلًا على نجاح استخدام فعلي أو شهادة WCAG.
