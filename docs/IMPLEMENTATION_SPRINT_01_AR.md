## حماية السجلات والخصوصية

- بقي مفتاح التخزين **`wejdan-fit-app-v1`**؛ لم تُحذف أو تُحوّل سجلات قديمة تلقائيًا.
- `setMetrics` حقل جديد اختياري؛ الجلسات القديمة التي تحتوي `metrics` تبقى قابلة للعرض.
- النسخة الاحتياطية يجب تصديرها من الجهاز الحقيقي قبل أي دمج؛ التخزين يعتمد على `localStorage`، وليس مزامنة سحابية.
- يحتفظ مستودع GitHub بالكود والبيانات المرجعية فقط، دون سجلات شخصية أو تقارير طبية أو نسخ احتياطية خاصة.
- تقييم الأعراض لا يجيز تمرينًا محظورًا طبياً ولا يحل محل الطبيبة. ما زالت فيديوهات مساري الـ25 غير معتمدة.

## الاختبارات التي شُغّلت

```
node --check app.js
node --check fit-core.js
node tests/regression.js
node tests/fit-core.test.js
node tests/masari-merge.test.js
python tests/browser_smoke.py
```

- اختبارات Node: ناجحة.
- اختبار واجهة Chromium مع صفحة HTML/JS محمّلة في ذاكرة المتصفح (بسبب تقييد الوصول الشبكي داخل بيئة الفحص): نجح التنقل وتسجيل حصة جزئية ثم كاملة، الحفظ بعد إعادة إنشاء الصفحة، التمارين والوصفات، الوجبة وتكرارها وتعديلها، سجل الأعراض؛ بلا خطأ JavaScript أو تمرير أفقي على عرض 390px.
- **ليس إثباتًا** لتشغيل HTTPS وService Worker على iPhone، أو لاستمرارية التخزين بعد ترقية فعلية في Safari أو Chrome، أو للتحقق الغذائي.

## المتبقي من خطة المهام الـ49

أهم بنود `P0` التي **لا تزال غير مغلقة**: النسخ الاحتياطي والاستعادة الواقعيان على الهاتف، ترحيل schema بإصدارات كاملة، تقييم مسببات الحساسية من ملصقات المنتجات، مصادر غذائية موثوقة لبيانات الحصص، تسجيل تعليمات الطبيبة التفصيلية داخل الإعدادات بطريقة آمنة، معاينة PWA مستقلة لا تشارك أصل التخزين مع الإنتاج، واختبار Safari وVoiceOver.

كذلك تبقى بعض `P1/P2` غير منفذة: مؤشرات التحسن الإحصائي الموثوق، بدائل مدققة طبيًا لكل تمرين، قوائم التسوق، تغيير الحجم الغذائي لوصفات مساري من مصادر معتمدة، تقارير متقدمة، دعم اختيارات الوضع الهادئ بحسب الظروف، التزامن بين الأجهزة (اختياري)، وتكاملات الصحة بأذونات خاصة.

**قرار الإطلاق:** `NO-GO FOR PRODUCTION` إلى أن تنجح اختبارات النسخ الحقيقية والتثبيت على iPhone ومراجعة المحتوى الطبي/الغذائي. لا تدمج Draft PR تلقائيًا.
